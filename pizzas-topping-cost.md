# [Задача про пиццу от McKinsey](https://datalemur.com/questions/pizzas-topping-cost)

Вы — консультант крупной сети пиццерий, которая планирует провести акцию со специальной фиксированной ценой на любые пиццы с тремя начинками, и пытаетесь оценить связанные с этим расходы.

Имея список начинок для пиццы, рассмотрите все возможные варианты пицц из 3 ингредиентов и выведите суммарную стоимость этих 3 начинок. Отсортируйте результаты так, чтобы варианты с наибольшей суммарной стоимостью были вверху, а далее — по возрастанию названий начинок.

При совпадении стоимости сортируйте ингредиенты в алфавитном порядке, начиная с первого ингредиента, затем по второму и третьему.

P.S. Будьте внимательны к пробелам (или их отсутствию) между ингредиентами. Ориентируйтесь на пример вывода (Example Output).

**Примечания:**

* Не выводите пиццы с повторяющимися начинками. Например: «Pepperoni,Pepperoni,Onion Pizza».
* Ингредиенты внутри названия должны быть указаны строго в алфавитном порядке. Например: «Chicken,Onions,Sausage». Вариант «Onion,Sausage,Chicken» является недопустимым.

Это задача про мои любимые non-equi join-ы. Суть такая, что сначала даем каждому топпингу id-шник и потом делаем самосоединение через сравнение. В оригинале предлагают сразу через сравнение строк идти, без добавления id. Но мне такой способ кажется менее контролируемым и прозрачным.

```sql
WITH filtered AS (
  SELECT
    *,
    ROW_NUMBER() OVER (ORDER BY topping_name) as rn
  FROM pizza_toppings
)
  SELECT
    f.topping_name || ',' || f2.topping_name || ',' || f3.topping_name AS toppings,
    f.ingredient_cost + f2.ingredient_cost + f3.ingredient_cost as sum_per_set
  from filtered f
  JOIN filtered f2 ON f.rn < f2.rn
  JOIN filtered f3 ON f2.rn < f3.rn
  ORDER BY sum_per_set DESC, toppings ASC;
 ```
